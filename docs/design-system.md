# 视觉、动效与交互设计规范

- 状态：P0 产品规范，随 MVP 一同交付
- 设计语言：Signal Deck（信号甲板）
- 更新日期：2026-11-05
- 适用范围：MyGo WebView 桌面应用，macOS 优先，兼容 Linux/Windows

## 1. 设计目标

“美观”不是开发完成后的皮肤，也不是可选加分项。对一个开源桌面小工具，它直接决定三件事：

1. **首次理解**：用户能否在几秒内看出“哪里异常、为什么异常、关掉会发生什么”；
2. **下载转化**：README 首图和 20 秒 GIF 能否在未安装前讲清产品价值；
3. **持续使用**：高频采样时界面是否稳定、可信、低干扰，而不是看起来像一块会跳动的机房大屏。

因此本项目把视觉质量、动效质量和交互质量定义为与采集、归因、安全回收同等级的 P0 交付物。

设计追求不是“炫酷”，而是：

> **让进程、会话、资源消耗和操作风险之间的关系一眼可见，并让用户愿意把它留在菜单栏里。**

视觉方向借鉴 CleanMyMac X 的克制留白、清晰层级、大字号主结论和流畅状态动效，但不做克隆：本项目使用石墨/薄荷的独立识别系统，**不使用粉色**，也不照搬其图标、布局或品牌表达。

## 2. 设计语言：Signal Deck

Signal Deck 是“安静的精密仪器”与“持续生长的任务生命线”的结合：

- **仪器感**来自稳定的网格、明确的数值、克制的中性色和一致的交互反馈；
- **生命感**来自任务热力树、生命周期河流和进程出生/退出事件；
- **安全感**来自危险范围的可视化、受保护节点的清晰边界，以及不夸张、不误导的动作反馈。

人格关键词：冷静、精确、可观察、有人情味。

避免：

- 黑底霓虹、发光边框、赛博朋克 HUD；
- “AI 大脑/魔法球/粒子网络”等与证据无关的装饰；
- 玻璃拟态卡片堆叠；
- 每个数字都跳动、每块面板都呼吸的“机房大屏”；
- 用红色和橙色制造紧张感；
- 大量圆角卡片、渐变按钮、无意义 3D；
- 依赖远程字体、远程图片或联网素材。

## 3. 3–20–60 体验目标

视觉和动效必须支撑以下三层体验，而不是只服务静态截图。

### 3 秒：看懂当前状态

用户只看到首屏，就能读出：

- 当前是否处于资源压力；
- 最主要的 1–3 个任务；
- 有多少资源疑似可以安全回收；
- 是否存在需要立刻关注的异常。

视觉证据：一句明确结论 + 压力任务 + 可回收容量，不要求用户先读图表坐标。

### 20 秒：理解问题为什么发生

用户通过任务热力树和生命周期河流看到：

- 哪个 Agent 根任务产生了大量后代；
- 哪些后代在会话结束后仍然存活；
- 哪个任务最旧、最闲、最重复；
- 哪些节点受保护，哪些节点在回收范围内。

视觉证据：进程树层级、时间事件、增长趋势和风险原因能够互相对应。

### 60 秒：完成一次可信任的回收

用户完成：

```text
选择候选
→ 查看爆炸半径
→ 检查受保护节点
→ 确认优雅停止
→ 看到逐 PID 结果
→ 验证资源下降并写入审计
```

视觉证据：动作过程中的高亮、进度和结果必须与真实状态一致；动画不能掩盖失败或延迟语义更新。

## 4. 设计原则

### 4.1 证据先于装饰

任何颜色、面积、动画和角标都必须对应一个可解释的字段或事件。没有证据支持的“健康分”“AI 光环”或动态背景一律删除。

### 4.2 层级先于密度

桌面端可以承载高密度信息，但首屏必须只保留一条主结论。PID、端口、完整命令行等细节通过下钻出现，而不是一开始铺满。

### 4.3 动效解释变化

动效用于表达：

- 新任务出现；
- 子进程爆发；
- 选中节点与详情之间的空间关系；
- 回收影响范围；
- 动作成功、失败或仍待确认。

动效不用于填补空白、制造科技感或让静态页面“显得活”。

### 4.4 默认安静

空闲页面不使用抢占注意力的循环动画，不做扫描线、粒子流或数字滚动。品牌标记、加载指示和骨架可以使用低强度循环动效，但必须远离主结论、低频且遵守 `prefers-reduced-motion`。实时图表只更新数据，不持续重绘装饰。

### 4.5 动画不承载状态

业务状态先更新，再由动画表现。任何按钮可用性、确认结果、错误提示都不能依赖 `animationend` / `transitionend`。

### 4.6 可访问性是视觉质量的一部分

颜色不是唯一信息通道；所有图表有文本/表格替代；键盘可以到达所有操作；减少动态效果模式下信息完整。

### 4.7 离线也完整

字体、图标、插图和主题资源不得依赖 Google Fonts、CDN 图片或联网字体。当前 macOS 版本优先使用系统字体，并保留本地/系统回退；所有界面资产随应用分发或由系统提供。

## 5. 视觉系统

### 5.1 品牌与色彩策略

主视觉采用“石墨黑/瓷白 + 薄荷青 + 资源蓝”：

- 石墨黑/瓷白负责层级与长时间阅读；
- 薄荷青表示当前交互、选中和实时状态；
- 资源蓝表示 RSS、子进程数量等中性数据系列；
- 琥珀/珊瑚红只用于风险、告警和破坏性动作；
- 绿色只用于明确的健康结果，不作为大面积品牌色。

整体气质参考 CleanMyMac X 的简约、留白和流畅层次，但保持独立的石墨/薄荷识别系统。界面不使用粉色作为品牌色、背景色或大面积状态色。

暗色优先，同时提供完整亮色主题。主题跟随系统，也可以手动切换。

### 5.3 字体

- UI：`SF Pro Display` / `SF Pro Text`，macOS 中文回退 `PingFang SC`，并提供 `Noto Sans SC` 与系统无衬线回退；
- 数据/命令行：`SFMono-Regular`，回退 `JetBrains Mono`、`Cascadia Code` 和系统等宽字体；
- 当前不加载远程字体，不依赖 Google Fonts 或 CDN；
- 其他平台回退到系统可用字体；正式跨平台发行前应补齐本地字体策略；
- 数字使用 `font-variant-numeric: tabular-nums`；
- PID、端口、容量、耗时优先使用 mono 字体。

字号层级：

| Token | 字号/行高 | 用途 |
|---|---|---|
| `display` | 42–62/1.04 | 首屏一句结论，仅一个 |
| `h1` | 23–31/1.15 | 页面标题 |
| `h2` | 18–22/1.3 | 区块标题 |
| `body` | 14–16/1.55 | 主要阅读文本 |
| `compact` | 12–13/1.45 | 表格与紧凑数据 |
| `caption` | 10–11.5/1.35 | 元数据与标签，不承载关键操作 |

关键正文和操作文字不使用 12px 以下字号；当前仍有少量 9.5–11.5px 的图表刻度和辅助标签，后续版本应继续减少。关键信息不能只靠小号元数据表达，操作按钮文字不得依赖 `letter-spacing` 或全大写提升辨识度。

### 5.4 形状、间距与层级

- 8px 基础节奏：4 / 8 / 12 / 16 / 24 / 32 / 48；
- 当前圆角 token 为 12 / 18 / 26 / 32px；数据行、面板、抽屉和对话框按层级使用，不把所有元素都做成圆角胶囊；
- 主要依赖 surface 明度、1px 边框和留白分层，不依赖大面积阴影；
- 阴影只用于对话框、命令面板和浮动详情，普通卡片不加悬浮阴影；
- 图标使用 Lucide，统一尺寸与描边；禁止用 emoji 作为结构图标；
- 桌面图标操作最小命中区 32×32px，主操作 40×40px；键盘焦点始终可见。

### 5.5 风险与状态编码

| 状态 | 颜色 | 必须同时出现的非颜色信号 | 动作含义 |
|---|---|---|---|
| Healthy / 正常 | 绿色 | 圆点 + “正常”文本 | 无建议 |
| Attention / 关注 | 琥珀 | 三角警示图标 + 原因 | 建议观察，不一定回收 |
| Reclaim / 回收候选 | 珊瑚 | 环状标记 + “候选”文本 + 规则证据 | 需要预览后确认 |
| Protected / 受保护 | 中性灰蓝 | 锁图标 + 斜线纹理 | 不可选择停止 |
| Blocked / 阻断 | 中性 + 红色边框 | 禁止图标 + 阻断原因 | 不允许执行 |
| Destructive / 破坏性确认 | 红色 | 明确动词 + 影响范围 | 仅在确认阶段出现 |

颜色不能单独表达风险；图表、列表和确认面板都必须提供图标、文本或纹理。

## 6. 页面布局

### 6.1 App Shell

- 最小支持窗口：1024×720；
- 推荐窗口：1440×900；
- 12 列网格，桌面 gutter 24px；
- 左侧导航在宽屏为 208px，可折叠为 64px；
- 顶部为 52px 可拖拽区域，兼容 macOS traffic lights；
- 全局搜索/命令面板入口固定，支持 `Cmd/Ctrl+K`；
- 主内容区设置最大宽度，避免超宽屏上信息被拉散。

### 6.2 概览页

首屏采用“结论优先”的非对称布局：

```text
┌─────────────────────────────────────────────────────┐
│ 状态带：CPU / Memory / Swap / Tasks / Agents         │
├───────────────────────────────────┬─────────────────┤
│ 一句话结论 + 当前压力趋势          │ 可回收容量       │
├───────────────────────────────────┴─────────────────┤
│ 任务热力树（主视觉，约占 7/12）   │ Top 任务（5/12） │
├─────────────────────────────────────────────────────┤
│ 生命周期河流（最近 15 分钟）                        │
└─────────────────────────────────────────────────────┘
```

- 一句话结论必须是完整句子，包含任务名、数值和时间窗口；
- 可回收容量使用“预计释放 4.2 GB / 12 个进程”，不使用模糊评分；
- 指标区采用固定宽度数字槽位，数值变化不推动布局；
- 首个数据未到达时展示保留尺寸的 skeleton，不显示空白大图；
- 底部趋势图不抢占首屏主结论。

### 6.3 任务页

- 默认按“当前压力贡献”排序，可切换 CPU、RSS、时长、子进程数；
- 大于 100 行启用虚拟列表；
- 风险列固定宽度并包含图标、文字和原因摘要；
- 展开任务树时不跳动整行，使用稳定的 chevron 和固定行高；
- 选中行与详情之间使用空间连续感：详情抽屉从右侧进入，选中行保持高亮；
- 批量选择只允许同类型、同安全等级的任务进入同一动作计划。

### 6.4 详情与回收确认

- 详情抽屉宽度 360–420px，不覆盖主结论区；
- 分为摘要、进程树、趋势、证据与建议；
- 回收确认使用独立全高面板或对话框，不使用普通按钮旁的小 popover；
- “爆炸半径预览”必须先于最终确认出现；
- 受保护节点固定、不可选择，并显示保护原因；
- 动作进度按 PID 展示“等待 / 已发送 / 已退出 / 失败”；
- 结果不自动关闭确认面板，直到用户看清最终状态。

## 7. 三个签名视图

### 7.1 任务热力树

**回答的问题：谁在占内存，资源集中在哪一层？**

- 层级默认最多 2 层：任务 → 会话/进程组；第三层按需下钻；
- 面积 = RSS；CPU 通过同一色相内的亮度/透明度表达，不使用红橙色；
- 风险通过图标、描边和纹理表达；
- 顶部始终展示图例、时间窗口和总量；
- 点击节点打开详情；键盘 Enter/Space 下钻，Backspace 返回；
- 小于 200 个节点用 SVG，200–1000 个节点用 Canvas，超过 1000 个先聚合或预过滤；
- 一级展示超过 1000 个进程时，合并为“其他”并提供列表入口。

动效：

- 首次加载只做一次 180ms 的淡入；
- 常规采样更新不逐个动画缩放面积，避免 1Hz 重排；
- 风险状态从正常变为关注时，标记一次性淡入 160ms；
- 下钻使用 220ms 的空间展开/淡入，减少模式立即切换。

文本降级：同一数据必须可通过“任务树表”查看，列包含名称、RSS、CPU、进程数、风险和证据摘要。

### 7.2 生命周期河流

**回答的问题：这些进程是什么时候出现、什么时候失控、为什么还没退出？**

- 横轴为时间，纵轴为任务；
- 每个任务一条泳道，带宽表示进程数，颜色/明度表示 CPU 或活动度；
- 标记进程出生、退出、子进程爆发、端口变化和长时间低活动；
- 支持 5 分钟 / 15 分钟 / 1 小时 / 6 小时窗口；
- 支持暂停自动滚动、拖拽缩放和重置；
- 当前值用静态端点与数值标签，不使用持续呼吸动画；
- 事件点可聚焦，工具提示显示时间、PID、任务归属和证据。

动效：

- 新事件以 120ms 淡入，不弹跳；
- 时间窗口切换使用 220ms 交叉淡入；
- 暂停/恢复只改变数据行为，不用动画表示；
- 不使用视差、扫描线、粒子流或循环渐变。

文本降级：提供事件表和当前摘要，至少包含时间、事件、任务、PID、规则和资源变化。

### 7.3 爆炸半径预览

**回答的问题：如果我点下去，究竟会关掉什么、保留什么、可能影响什么？**

- 在任务树上叠加动作范围；
- 将节点分为：将停止、已受保护、被阻断、关联容器、可能影响 IDE/终端；
- 用纹理、锁图标、删除线/边框和文本标签区分，不只依赖颜色；
- 顶部显示影响总量：进程数、RSS、端口、容器和预计用户影响；
- 默认只预选有明确宿主关系的重复/孤立后代进程组；
- 任何“可能影响当前 IDE/终端”的节点必须显示原因和阻断/解锁状态。

动效：

- 打开预览时，受影响子树用一次性 300ms 高亮从根到叶扩散；
- 受保护节点不参与高亮，保持静止；
- 用户切换选择时只做 120ms 边框/底色变化；
- 确认按钮的可用状态与动画无关；
- 动作完成后，节点以 220ms 淡出并更新摘要，失败节点保持原位并标红。

文本降级：确认面板内始终列出完整 PID 表、信号、保护原因、预计回收量和失败处理方式。

## 8. 动效规范

### 8.1 动效 token

| 场景 | 时长 | Easing | 说明 |
|---|---:|---|---|
| 按压反馈 | 80ms | standard | 只改透明度/背景，不移动布局 |
| Hover / Focus | 120ms | standard | 边框、背景和焦点环 |
| 小型状态切换 | 160ms | enter | 风险标记、tooltip、选中态 |
| 抽屉 / 面板 | 220ms | enter / exit | 右侧进入，退出略快 |
| 页面/空间转换 | 300ms | enter | 仅在确实表达层级变化时使用 |
| 图表首现 | 180ms | enter | 一次性淡入，不做全图缩放 |
| 动作结果 | 220–280ms | standard | 淡出/收敛，不弹跳 |

- 统一 token，避免每个组件复制任意时长；
- 进入使用 `--ease-enter`，退出使用 `--ease-exit`；
- 数据密集列表不使用 overshoot/back easing；
- 动画只使用 `transform`、`opacity`，必要时允许颜色和 SVG 属性过渡；
- 不通过动画改变语义状态；
- 同时进行的动画不超过 2 个视觉区域。

### 8.2 每个视图的关键动效预算

| 视图 | 关键动效 | 禁止 |
|---|---|---|
| 概览 | 结论与热力树一次性进入；风险标记一次性出现 | 指标数字持续跳动、卡片循环呼吸 |
| 任务 | 选中行与详情抽屉空间连接 | 行进入时逐行 bounce、表格自动滚动 |
| 生命周期 | 新事件淡入、窗口交叉切换 | 持续扫描线、河流波动装饰 |
| 回收预览 | 受影响子树一次性高亮、完成淡出 | 红色闪烁、震屏、倒计时压迫 |
| AI 助手 | 回答分段出现，引用证据定位 | 打字机效果拖慢阅读、假思考动画 |

### 8.3 Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- 减少动态模式必须直接呈现最终信息状态；
- 不依赖动画结束才更新业务状态；
- 图表暂停/恢复、焦点和操作反馈仍完整可用；
- 视觉快照测试同时覆盖默认与 reduced-motion 模式。

## 9. 技术实现约束

- 使用 CSS transitions/animations + Web Animations API，不为小型应用默认引入 GSAP；
- 如后续需要编排复杂共享元素，可优先评估 View Transitions API 的渐进增强，必须有回退；
- 实时曲线由 uPlot（Canvas）绘制，避免每条数据更新 React DOM；
- 树图布局使用 `d3-hierarchy` 等模块化工具，渲染层自行控制 SVG/Canvas；
- 大于 100 行列表使用虚拟化；
- 高频事件先在后端聚合，前端按可见帧率批处理；
- 所有图表提供表格/摘要组件；
- 图标和演示素材随包分发，字体使用离线系统栈且不发起远程字体请求；
- 不使用自动播放的高清背景视频，不在主窗口加载远程 iframe。

### 9.1 性能预算

参考设备：MacBook Air M1，1440×900，浏览器缩放 100%。

| 指标 | 目标 |
|---|---|
| 首屏结构出现 | <100ms（skeleton 或缓存） |
| 缓存快照可见 | <500ms |
| 新鲜快照可见 | <2s；权限受限时显示持续进度 |
| 采样更新 P95 帧时间 | <16.7ms |
| 单次 UI 更新主线程 | <16ms |
| 长任务 | 采样更新期间无 >50ms 长任务 |
| 常规动画 | 稳定 60fps，无明显掉帧 |
| 布局偏移 | CLS <0.05 |
| 空闲窗口 | 无高注意力循环动画；仅允许低强度品牌/加载动效 |
| 常驻 CPU | 平均 <1.5%（8 核参考机） |
| 内存占用 | 目标稳定 <250MB RSS |
| 7 天数据库 | <200MB |

性能达标不是体验达标的替代：即使 60fps，如果用户仍看不出主结论，视觉设计仍未完成。

## 10. 可访问性验收

- 正文文本对比度 ≥4.5:1；非文本交互元素 ≥3:1；
- 所有交互支持键盘，焦点顺序与视觉顺序一致；
- 焦点环始终可见，不被 sticky header、抽屉或滚动容器遮挡；
- 颜色、面积、纹理、图标和文字组合使用，风险不只靠色相；
- 图表支持键盘聚焦、暂停和文本替代；
- 任务树支持展开/折叠、进入详情和返回；
- 危险动作有明确动词、影响范围和二次确认；
- 动态状态使用适当的 `role="status"`，不逐 tick 播报所有指标；
- 支持 200% 缩放和系统大字体；
- 减少动态模式、亮色/暗色模式均完整测试。

## 12. 视觉验收清单

发布任何 UI 版本前必须通过：

### 信息层级

- [ ] 首屏 3 秒内能说出当前主要压力任务；
- [ ] 一句话结论包含任务、数值和时间窗口；
- [ ] 首屏只有一条主结论，不出现多个竞争性大数字；
- [ ] 数字、单位、时间窗口和风险原因始终可见；
- [ ] 任何异常可视化都能下钻到证据。

### 视觉稳定性

- [ ] 1Hz 更新时不跳布局、不闪烁、不自动滚动；
- [ ] 数字使用等宽数字或预留宽度；
- [ ] 列表加载不产生横向滚动，详情抽屉不遮挡关键操作；
- [ ] 1024×720、1280×800、1440×900 均无关键内容截断；
- [ ] skeleton 与真实内容尺寸一致。

### 动效

- [ ] 每个视图最多 1–2 个关键动效；
- [ ] 空闲时没有抢占注意力的循环动画；品牌/加载动效低频且可被 reduced-motion 关闭；
- [ ] 动画不依赖 `animationend` 才能完成业务状态；
- [ ] reduced-motion 下信息完整、操作可用；
- [ ] 动作成功/失败有非动画反馈；
- [ ] 60fps 抽测通过，无持续长任务。

### 可访问性

### 传播素材

## 13. 反模式清单

以下任一项出现，视为 UI 未达到 P0：

- 用霓虹发光、暗角、网格背景代替信息层级；
- 用红色/橙色装饰普通元素；
- 用“健康分 62”代替可解释证据；
- 每秒让所有卡片、数字和图表一起重播动画；
- 统计数字宽度变化导致表格左右抖动；
- 用 hover-only 暴露关键证据；
- 在动作确认里隐藏 PID、保护原因或信号类型；
- 用动画延迟按钮的可用状态或操作结果；
- 图表只有颜色编码、没有表格/摘要；
- README 使用概念图但实际应用未实现；
- 为了视觉效果引入大型 3D/视频/动画运行时，拖高常驻资源。
